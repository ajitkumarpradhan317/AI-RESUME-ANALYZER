# Known limitations (honest list for the project report / viva)

- **Keyword matching is statistical, not semantic.** TF-IDF plus an alias table cannot understand meaning ("built dashboards" vs "data visualisation"). The score is a guide, not a real ATS result.
- **Skill roadmap and bullet rewrites are template-based**, not generated by an AI model; project ideas exist only for common skills.
- **Resume parsing:** text-based PDFs and .docx only (no OCR for scanned images). Complex layouts (columns, tables) can scramble text order.
- **Remember-me** relies on a browser cookie set from a small script and read with `st.context.cookies` (Streamlit >= 1.37). If a browser blocks it, users simply log in normally.
- **Single Streamlit process:** logins live in server memory, so a restart signs everyone out and heavy use shares one CPU. Free hosting sleeps when idle.
- **No CAPTCHA / IP rate limiting inside the app** (Streamlit cannot see client IPs). Put Cloudflare or similar in front for public launches.
- **Account lockout** can be abused to lock a known user out for 15 minutes.
- **Sign-up still reveals** whether a username or email is already taken.
- **Admin analytics are anonymised** but small colleges may often see "not enough data" (groups below 3 students are hidden by design).
- **Test coverage:** logic and security rules are unit tested; the database queries and screens are covered by integration tests that need a real Postgres (see README).
